# کنسول فروشنده (Vendor Console)

پنل مستقلی برای **توسعه‌دهنده/فروشنده** که مجوز استفاده از نرم‌افزار را برای هر شرکت تعیین می‌کند. هیچ‌جای ظاهر برنامه به آن لینک نشده است و برای مالک، مدیر و کاربران وجود ندارد.

> مدل: هر شرکت یک **نصب** جدا از AISO دارد (یک سرور، یک پایگاه داده). کنسول، شرکت و مجوزِ همان نصب را تعریف می‌کند. برنامه چندشرکتی (چند مشتری روی یک پایگاه داده) نیست.

## ورود

1. با `php artisan aiso:vendor-credentials` نام کاربری و رمز بسازید (فقط **هش** در `.env` ذخیره می‌شود؛ مقدار اصلی یک‌بار چاپ می‌شود).
2. در **همان صفحهٔ ورود معمولی** با این نام کاربری و رمز وارد شوید؛ به‌جای برنامه، کنسول باز می‌شود (`/vendor`).
3. هر کس دیگری (حتی مالک) برای `/api/vendor/*` پاسخ **۴۰۴** می‌گیرد، مثل مسیری که وجود ندارد.

| مورد | توضیح |
|---|---|
| نام کاربری | با HMAC-SHA256 (با salt) هش می‌شود و در زمان ثابت مقایسه می‌شود |
| رمز | bcrypt |
| خاموش کردن کنسول | `php artisan aiso:vendor-credentials --remove` (یا خالی گذاشتن متغیرها) |
| تعویض | دوباره همان دستور را اجرا کنید |
| چاپ بدون نوشتن در `.env` | `--print-only` |
| پایان نشست | پس از ۳۰ دقیقه بی‌کاری (`AISO_VENDOR_IDLE_MINUTES`) |
| محدودیت تلاش | ۱۰ ورود ناموفق در دقیقه برای هر آدرس (برای همهٔ ورودها) |

برای چند نصب می‌توانید همان سه خط `AISO_VENDOR_*` را در `.env` همهٔ نصب‌ها بگذارید تا با یک نام کاربری وارد شوید.

## امنیت بیشتر: توکن دستگاه و کد احراز هویت

سه لایه، هر کدام جدا قابل روشن و خاموش شدن:

| لایه | چیست | دستور |
|---|---|---|
| ۱. نام کاربری + رمز | هش در `.env` | `php artisan aiso:vendor-credentials` |
| ۲. **توکن دستگاه** | مرورگر شما باید کوکی `aiso_dev` با مقدار توکن را داشته باشد. فقط SHA-256 توکن ذخیره می‌شود. | ساخت/تعویض: `--token-only`، خاموش: `--disable-token` |
| ۳. **کد احراز هویت (TOTP)** | کد ۶ رقمی Google Authenticator / Authy / Microsoft Authenticator (RFC 6238) | روشن/تعویض: `--totp-only`، خاموش: `--disable-totp` |

**توکن دستگاه:** بدون کوکی، حتی نام کاربری و رمز درست مثل یک ورود اشتباه معمولی رد می‌شود (پیام «شناسه کاربر یا رمز عبور نادرست است»)، پس کسی نمی‌فهمد کنسولی وجود دارد. کوکی در **هر درخواست** کنسول بررسی می‌شود؛ یعنی دزدیدن نشست (session) بدون کوکی به‌تنهایی فایده‌ای ندارد.

کوکی را دستی بگذارید (Chrome/Edge: `F12` ← `Application` ← `Cookies` ← آدرس سایت ← یک ردیف جدید):

| فیلد | مقدار |
|---|---|
| Name | `aiso_dev` |
| Value | توکنی که دستور چاپ کرد |
| Path | `/` |
| Expires | یک سال بعد |
| HttpOnly | ✓ |
| SameSite | Strict |
| Secure | ✓ (فقط وقتی سایت روی https است) |

**کد احراز هویت:** پس از رمز درست، فرم ورود یک خانهٔ «کد تأیید» نشان می‌دهد. رمز به‌تنهایی چیزی باز نمی‌کند، هر کد فقط یک‌بار قبول می‌شود (جلوگیری از بازپخش) و بعد از ۵ دقیقه مرحلهٔ رمز منقضی می‌شود. راز base32 را در برنامهٔ احراز هویت با «Enter a setup key» وارد کنید (نوع Time based، ۶ رقم). این راز باید در `.env` خوانا باشد، چون سرور برای بررسی کد به آن نیاز دارد.

نکات: روی سرور واقعی حتماً **https** بگذارید (توکن کوکی مثل رمز، روی http قابل شنود است)؛ ساعت سرور باید درست باشد (TOTP به زمان وابسته است)؛ ترتیب پیشنهادی: رمز + توکن دستگاه + TOTP.

## بخش‌های کنسول

- **شرکت:** نام، نام حقوقی، رابط، تماس، یادداشت خصوصی و شناسهٔ نصب.
- **مجوز:**
  - مدت استفاده: نامحدود، یک‌ساله، آزمایشی ۳۰ روزه، یا سفارشی (تعداد روز یا تاریخ پایان) از تاریخ شروع دلخواه.
  - تمدید، تعلیق (با علت) و ازسرگیری.
  - قوانین: روزهای فقط‌خواندنی پس از پایان، سقف کاربر فعال، سقف پروژهٔ فعال، مجاز بودن تخصیص با هوش مصنوعی، مجاز بودن پیام‌رسان بله.
- **مالک:** ساخت یا تعیین حساب مالک (مالک قبلی مدیر می‌شود) و بازنشانی رمز. رمز موقت فقط یک‌بار نمایش داده می‌شود و کاربر باید در اولین ورود عوضش کند.
- **کاربران:** ساخت مدیر و کاربران اجرایی، بازنشانی رمز، فعال/غیرفعال. (سقف مجوز برای کنسول اعمال نمی‌شود.)
- **تنظیمات شروع:** نام پروژه، زبان، سقف وظایف، تأیید اتمام، پیام‌رسان.
- **گزارش فعالیت:** سابقهٔ کارهای فروشنده؛ جدا از «گزارش ممیزی» است و مالک و مدیر آن را نمی‌بینند.

## اثر مجوز روی برنامه

| وضعیت | رفتار |
|---|---|
| بدون شرکت تعریف‌شده | بدون هیچ محدودیتی (نصب‌های قدیمی مثل قبل کار می‌کنند) |
| فعال / به‌زودی منقضی | عادی (در کنسول ۱۴ روز مانده «به‌زودی منقضی» نشان داده می‌شود) |
| منقضی در بازهٔ تنفس | ورود و مشاهده آزاد، هر تغییری با خطای ۴۲۳ رد می‌شود |
| منقضی پس از تنفس / تعلیق / شروع‌نشده | ورود رد می‌شود و نشست‌های باز بسته می‌شوند؛ پیام علت در صفحهٔ ورود دیده می‌شود |

سقف‌ها: ساخت یا فعال‌سازی کاربر توسط مالک و ورود Excel که کاربر یا پروژهٔ تازه بسازد، از سقف مجوز عبور نمی‌کنند. اگر تخصیص با هوش مصنوعی یا بله مجاز نباشد، تخصیص به الگوریتم برمی‌گردد و ارسال پیام بله انجام نمی‌شود.
