# AISO — MVP 0.2

Operations dependency engine, **multi-project scheduling**, task assignment and dashboards, built from the project document `AISO.docx`.

- **Backend**: Spring Boot 4.1 (Java 21), JPA + Flyway, Spring Security (JWT), Apache POI.
- **Frontend**: Next.js 16 (App Router, TypeScript, Tailwind 4). Persian (RTL) by default with an English toggle, light/dark theme, **Solar Hijri (Jalali) calendar** for every date.
- **Several projects are scheduled together** on shared resources. A manager ranks the projects; the optimiser honours that ranking strictly and fills every idle gap with lower-priority work, so wasted resource time is minimised.
- **Task assignment has two interchangeable methods**, switchable at runtime:
  1. **Algorithm**: deterministic dispatching rule (project priority, then the optimised plan's order, then critical path; resource capacity and per-user task limit respected; least-loaded user wins).
  2. **LLM**: a large language model reads the same project snapshot and proposes assignments with reasons. Its output is re-validated against the same hard constraints (and the project-priority rule) before anyone sees it.

In both modes the system only **proposes**. A manager approves, as the document requires ("no automatic change of the plan without manager approval").

## Multiple projects

- A project is created by importing an Excel file (`POST /api/import`, or *Excel import* in the UI). Choose an existing project or create a new one.
- **Adding a project to a schedule that is already running asks for the priorities first.** The import answers `PRIORITY_REQUIRED`, shows the ranking editor and a **before/after impact preview** (finish of every project, wasted resource time, utilisation). Nothing is stored until the manager confirms the ranking.
- Priorities can be changed any time on *Projects & priorities*, with a preview before applying. Due dates are optional and only used to report tardiness.
- Resources (and their capacity) are **shared**; operation ids are unique across projects; dependencies cannot cross projects.
- Strict priority: a higher-priority project is never delayed by a lower-priority one. Running (IN_PROGRESS) operations are never moved.
- How waste is minimised, and how it is measured, is in [docs/DESIGN.md](docs/DESIGN.md) §8.

## Persian and Solar Hijri support

- UI in Persian (RTL) or English; all dates are shown in the Solar Hijri calendar in Persian mode (Tehran time) and may be typed as Jalali dates (`1405/07/25`, Persian digits fine).
- **Excel**: the master template and the report can be downloaded in Persian (`?lang=fa`): Persian sheet names and headers, Persian values for statuses, Jalali dates, right-to-left sheets. The importer accepts Persian sheet names, headers and values (`فعال`, `پایان به شروع`, `بله` …), so a Persian template can be filled in and uploaded as it is.
- **Texts generated by the system** (errors, import findings, notifications, assignment reasons, history notes) are produced in Persian: error answers follow the language of the request; stored texts follow the owner's *Language of system texts* setting (default on a fresh install: Persian, `AISO_LANGUAGE`).

## Dashboards

| Role | Pages |
|---|---|
| **Owner** | System status (suspend/resume with reason), settings (incl. language of system texts), assignment method, users and roles, audit log, Excel import, data reset, failed-message count, everything the manager sees |
| **Manager** | Overview (projects, progress, projected finish, wasted resource time, critical operations, blocked/delayed/ready lists, resource utilisation, user workload), **Projects & priorities** (ranking, preview, due dates, archive), Task assignment (method switch, suggest, review, approve/reject), Operations (filter by project/status/resource/user, details, assign/unblock/approve/cancel), Plan (timeline per resource, per project), Reports (user performance, Excel export in Persian/English, failed messages), Excel import, Audit log |
| **Executive users (USER_1..3)** | Own tasks only: start, report progress, complete, report a problem, comment; own performance; notifications |

## Quick start

Requirements: JDK 21, Maven 3.9+, Node 20+. (If you have none of them, `.tools/` in this folder may already hold portable copies of JDK and Maven; the scripts below use them automatically.)

```powershell
# terminal 1 - backend on http://localhost:8080
./scripts/start-backend.ps1

# terminal 2 - frontend on http://localhost:3000
./scripts/start-frontend.ps1
```

Open http://localhost:3000.

First start seeds these accounts (user ids): `owner`, `manager`, `user1`, `user2`, `user3`.
The password is `ChangeMe!123` unless you set `AISO_SEED_PASSWORD` **before the first start**. Change it for anything beyond a local trial.

Then, as **owner**: Owner console → *Load sample data*, or *Excel import* → upload your own file (`test-data/M1-alpha.xlsx` and `M2-beta.xlsx` show two projects sharing machines). As **manager**: *Projects & priorities* to rank projects, *Task assignment* → *Suggest assignments* → *Approve*.

If port 8080 or 3000 is taken, set `SERVER_PORT` for the backend and `AISO_API_URL` for the frontend (e.g. `SERVER_PORT=8090`, `AISO_API_URL=http://localhost:8090`).

### Using the LLM method

Configure it in the **backend's environment** (nothing is stored in the database or sent to the browser):

```powershell
$env:ANTHROPIC_API_KEY = "<your key>"
$env:AISO_LLM_MODEL = "<model id>"       # required: there is no built-in default
./scripts/start-backend.ps1
```

Then switch the method on *Task assignment*. What leaves your server: operation ids/names/hours, project names and priorities, user ids/names and workload numbers, resource names and capacities. No contact details, passwords or audit data. If the LLM is not configured or the call fails (API error, refusal, unusable output) the run falls back to the algorithm **and says so** in the UI (banner, run history, audit log); set `aiso.llm.fallback-to-algorithm: false` to get an error instead.

## Configuration (backend, environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `SERVER_PORT` | `8080` | HTTP port |
| `AISO_DB_URL` / `AISO_DB_USER` / `AISO_DB_PASSWORD` | embedded H2 file `./data/aiso` | Use `jdbc:postgresql://host:5432/aiso` for PostgreSQL (driver and migrations included) |
| `AISO_JWT_SECRET` | random at startup | ≥ 32 chars. Set it, or every restart logs everyone out |
| `AISO_SEED_PASSWORD` | `ChangeMe!123` | Password of the seeded accounts (first start only) |
| `AISO_LANGUAGE` | `fa` | Language of system-generated texts on a **fresh** install (`fa` or `en`); the owner can change it later |
| `ANTHROPIC_API_KEY` | empty | Key for the LLM method |
| `AISO_LLM_MODEL` | empty | Model id for the LLM method (required together with the key) |

Frontend: `AISO_API_URL` (default `http://localhost:8080`). Behind HTTPS nothing else is needed. Over plain HTTP on a non-localhost host set `AISO_INSECURE_COOKIES=1`, otherwise the browser will not keep the secure session cookie.

Upgrading an existing installation is automatic: the database migrations (`V2`, `V3`) move existing operations into one project named after the old single-project settings.

## Excel input

Two layouts are accepted (the system detects which one it gets). Every file is **validated first**; nothing changes unless the whole file is valid, and each problem is reported with *sheet, row, column and description* (in Persian for a Persian request).

1. **Master template** (download it from the Excel import page, English or Persian): sheets `Resources`, `BOM`, `OPC`, `Predecessors`, `Users`, `Settings` — or their Persian names `منابع`، `قطعات`، `عملیات`، `پیش‌نیازها`، `کاربران`، `تنظیمات`. Optional column `Is_Mandatory` on `Predecessors`; `Dependency_Type` accepts `FINISH_TO_START` / `START_TO_START`.
2. **Simple layout**: sheets `opc` and `source` with Persian headers. Operation ids become `OP-001…`, resources `RES-001…`, items `ITM-<code>`. "Direct hours" is taken as the operation's total duration.

Validation covers: duplicate ids, unknown references, non-numeric/negative numbers, bad enum values, self-dependency, **dependency cycles** (reported as a path, never auto-removed), roles (OWNER can never come from an import; MANAGER only if the importer is OWNER), operation ids already used by another project, dependencies across projects, and structural changes to operations already started (rejected). Re-importing is an upsert by id; started operations keep their state.

## Known limits

- **The LLM method has not been exercised against a live model** (no key was available while building it). The request code compiles against the SDK and the validation of model output is unit-tested with synthetic answers, but the first real call is untested. Try it once with your key and check the run on the Task assignment page.
- **Messenger**: only the in-app inbox exists. The delivery seam (`NotificationService.deliver`) marks any other configured platform as FAILED visibly; no Telegram connector is written.
- **Backup/restore** is not coded. H2: copy the `data/` folder while the backend is stopped. PostgreSQL: `pg_dump` / `pg_restore`.
- **Owner transfer / owner password recovery** has no in-app path; recovering needs database access.
- No login rate limiting, no email-based password reset.
- Time is a continuous clock (no working calendar/shifts); an operation's `quantity` does not scale its hours.
- One Excel file = one project (no project column inside a file yet).
- Texts the system generates in Persian use Latin digits in numbers; dates use Persian digits.
- The audit table is append-only by application code. Making it tamper-proof at database level is a deployment task.
